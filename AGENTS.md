# Local personal job tracker

The personal tracker must stay local. Never deploy private data or configure a hosted personal tracker. GitHub receives generic source, synthetic tests and empty root templates only. Never commit `.local-data`, `.local-backups`, Gmail records, message IDs/hashes, credentials, tokens, private notes or exports. Run `npm test` and `npm run build` before publishing source changes.

When the user says **update the tracker**: implement the requested changes, run checks, publish source changes as appropriate, apply the tested code to the user's actual local installation, restart its localhost server, refresh the sidebar and verify the working site. Repository-only updates do not complete the task. Locate the actual installation; never substitute an empty clone for the user's records. Preserve `.local-data`, browser localStorage, deleted-record tombstones, private notes and the existing hostname/port. Use `npm run update:local` for clean-main updates after CI passes. Never use `git clean`, force checkout, or a hard reset on the personal installation.

When the user says **scan Gmail**: use the connected Gmail read/search tools to find application-related messages, including older messages not already processed. Review actual content; do not guess company, role, status or date. Skip unrelated mail, resolve ambiguous matches, and create a normalized local batch under `.local-data/`. Import with `npm run import:mail -- .local-data/reviewed-updates.json`. Message hashes ensure repeat scans do not duplicate events. Match existing IDs whenever known; distinct requisitions must keep distinct IDs. Do not send mail or upload mail data to GitHub. Refresh the local sidebar, verify updated records and preserve manual notes and newer manual statuses. Do not claim a scan happened unless messages were actually read and imported.

Preserve DFW-first sorting, location filters, work arrangement filters and existing status colors. Keep public root JSON templates empty. Use a stable localhost origin so existing browser notes remain available.

Manual updates are now persisted by the localhost `/api/workspace` endpoint in `.local-data/workspace.json`, shared by Chrome and the sidebar. Use `npm run mark -- --id <exact-id> --status Applied --date YYYY-MM-DD` for a user-confirmed application, or the API with its current revision for notes/edits. Never invent an application or treat opening an outbound link as applying. Preserve manual notes, stars, deletions and newer manual status timestamps. Refresh after external updates; stale browser writes must fail instead of replacing newer revisions.

Research must check the user's current resume graduation date, employer CPT policy, explicit work arrangement, internship term and deadlines. Do not infer onsite from a city, or CPT acceptance from historical H-1B sponsorship. Retain known ineligible/expired roles separately from the shortlist. Scholarship research is not requested; focus on internships. U.S. relocation roles are allowed, with DFW first. As of October 24, 2026 UTA's CPT page states that new elective requests are paused; re-check the official page when refreshing research. Employer acceptance and university authorization are separate checks.

The latest UI requirement is a simple white site with larger text and exactly two main tabs: Available jobs (all records whose current status is Not applied / Interested) and Applied (all submitted applications, regardless of outcome). A record must appear in exactly one tab. Applied contains status filters for Applied, OA, Interview, Accepted/offers, Rejected and Other, and the actual employer-reply history lives in each job's Details. Moving a status updates list membership. Keep job research, resume match details, recruiter information and old records preserved without adding extra main navigation or dashboards. Do not fabricate an OA, interview or acceptance merely to populate a category. Maintain DFW-first/remote sorting, location and arrangement filters, privacy and existing status colors. OA and generic Interview are now supported local statuses.
